## 2. 页面级增量设计

### 2.1 工作空间列表：归档筛选与归档态

- 工具栏搜索框右侧增加紧凑筛选：`全部 / 活动 / 已归档`（segmented 按钮组，视觉沿用现有页签 item 的描边+字号规范）。**仅团队空间响应归档筛选**，个人空间恒显示在全部与活动视图；默认「全部」。
- 归档空间卡片：类型 Tag 旁追加 `StatusTag status="warning"` 「已归档」；卡片可点击进入只读详情。四项指标与计数一律取服务端按可见范围计算的数值（见方案 6.6），前端不二次过滤。
- 计数文案随筛选变化：「N 个可访问工作空间」。
- 空态区分：无团队空间归档 → 归档筛选下显示「暂无已归档的团队空间」（有权限的说明文字）。

### 2.2 对话页签：历史对话（TW-03）

- 页签内容区顶部增加视图切换行（高约 40px，`panel` 内容容器内、不占用页头）：「新对话 / 历史对话」segmented 切换，默认新对话；切换写入路由 `?view=history`，刷新与深链可恢复。返回新对话即切回，原输入内容由组件自身状态保留（不做恢复承诺，见 3.3 错误行）。
- 历史视图占据同一内容区域，替换 Starter：
  - 工具栏：标题搜索框（placeholder「搜索对话标题」，290px 同规格）+ 分页信息；
  - 列表行（自定义行模式）：状态点（复用侧栏五色点语义）+ 标题（单行省略）+ 发起人 + 最近活动时间 + 最新运行状态 `StatusTag`；整行可点击进入 `/conversations/:runId`（服务端解析到 Session，兼容 Run ID 链接）；
  - 分页：「加载更多」按钮 + 游标分页（服务端会话汇总后分页，见方案 6.2）；到达末尾显示「已加载全部」；
  - 排序固定按最近活动时间倒序，首版不提供排序切换。
- 历史列表**固定为本人范围**：服务端按当前登录员工过滤，前端不提供「我的对话／团队共享」筛选，也不传递范围参数；发起人字段保留在行内展示（不做筛选器）。
- 空态两种（对应方案 3.3）：本人尚无对话（可发起时引导返回新对话；不可发起时提示「联系负责人添加可用 Agent 成员」，`data-testid="session-history-empty-own"`）；筛选无结果（提示「没有找到标题包含“X”的对话」+「清除筛选」按钮，`data-testid="session-history-empty-filter"`）。不再有空间级空态：其他成员的会话不进入本列表，也不显示数量。
- 小屏：≤520px 行内隐藏发起人，时间只保留短格式。

### 2.3 共享文件页签（TW-05）

- 页头搜索框：名称搜索（服务端搜索，名称含关键词即匹配），与上传按钮同排。
- 行结构在现有四列基础上调整为：图标 / 名称+说明行（大小 · 上传人 · 时间） / 状态 `StatusTag` / 操作区。状态映射：
  - 上传中 → `neutral`「上传中」；检查中/解析中 → `neutral`「处理中」；可引用 → 不显示 tag 或 `success`「可引用」；失败 → `danger`「失败」+ 名称旁 `el-tooltip` 展示失败原因；已移除 → 不出现在有效列表（逻辑移除，见空态）。
- 操作区：`引用到对话`（保留）+ `下载`（新增，plain 按钮）+ 更多下拉（「移除」仅对权限内条目显示；移除二次确认，文案说明逻辑移除与历史引用保留）。
- 权限：只读成员不渲染上传按钮与移除入口（保留引用与下载）；成员仅对自己上传的文件显示「移除」；负责人/管理员对所有文件显示。
- 版本与「上传新版本」入口属 P1（TW-07），P0 不渲染；文件行引用时携带的是不可变文件对象（服务端契约）。
- 空态区分：空间无文件 / 筛选无结果；上传失败文件仍在列表内以失败状态可见。

### 2.5 右栏 `WorkspaceInfoPanel` 增量（仅团队分支）

- 成员区改为两段式：
  - 「员工」段：保留现有头像×5 + 姓名串样式；摘要文案改为「`N` 位员工」；
  - 「Agent」段：条目为图标（`el-icon` 复用 Robot/CPU 类现有图标）+ 名称 + 5px 状态点（可用绿/已停用灰/不可用红）；摘要「`N` 个 Agent」，**不混入员工人数**（AC-18）。
- 成员区标题行增加「管理成员」文字按钮（负责人/管理员可见）→ 打开成员管理弹窗（2.6）。
- 面板底部（footer 上方）增加「空间设置」入口（仅负责人）→ 设置弹窗（2.7）。
- 归档态：身份卡类型 Tag 旁显示「已归档」，页脚提示改为只读说明。
- 小屏抽屉复用同一面板组件，行为一致。
- 个人空间分支：以上全部不渲染（组件内 `v-if="workspace.type === 'team'"`）。

### 2.6 成员管理弹窗（新，1A）

- `el-dialog` 600px，标题「管理成员」，内部分两段（「员工」/「Agent」分段标题 + 各自列表），底部 footer「关闭」。
- 员工段：
  - 每行：头像（现有首字圆形样式）/ 姓名 + 部门 / 角色（`el-select` 四值：负责人/管理员/成员/只读成员） / 移除按钮（二次确认）；
  - 角色下拉权限：负责人可改全员；管理员仅可改「成员/只读成员」且对自己与其他管理员禁用；最后负责人显示「负责人（唯一）」禁用下拉与移除；
  - 「添加员工」按钮：打开搜索选择（输入即搜索，服务端分页，仅返回姓名/部门最小字段；已加入者排除显示；离职/停用不可选）。
- Agent 段：
  - 每行：图标 + 名称 + 职责摘要 + 状态点；行操作：`开始对话`（所有成员可见）+ 管理操作（停用/重新启用/升级/移出，仅负责人；二次确认文案提示在途运行收敛）；
  - 状态为不可用时行内 tooltip 展示具体原因（平台未授权/版本失效/Runtime 不可用）；
  - 「添加 Agent」按钮：搜索平台已发布且允许加入的 Agent → 选中后展示详情确认区（职责、关联技能、所需工具、数据范围）→ 「确认加入」。
- 弹窗内无「可用能力」入口（方案 3.2 明确不另设）。
- 空态：员工段无成员显示「尚未添加员工」；Agent 段显示「尚未加入 Agent」+ 负责人可见「添加 Agent」引导、普通成员见「请联系负责人」提示（TW-02 空态行）。

### 2.7 空间设置弹窗（新，1A 入口 / 3 落地行为）

- `el-dialog` 520px，标题「空间设置」：
  - 名称/说明编辑（负责人；清空说明传 `null`，方案 3.3）；
  - 「转交负责人」区（负责人）：搜索选择现有成员 + 确认（文案：转交后你成为普通成员）；
  - 「退出空间」区（非负责人）：确认文案说明贡献与作者归属保留（TW-01）；
  - 「归档空间」区（负责人，批次 3 行为生效）：确认文案 + 运行中冲突提示（TW-06）。
- 归档空间的恢复入口：归档详情页页头下提示条（`el-alert` 风格，仅负责人显示）「该空间已归档 · 恢复空间」。
- **归档后的写入口必须全部隐藏（3-T3 写入口审计）**：不只是详情页的「新对话／切换／上传／引用到对话／续写／重试」，还包括 **成员与 Agent 管理弹窗**（添加员工、角色下拉、添加 Agent、停用/升级/移出/开始对话）、**全局新对话的空间选择器**（不得列出归档团队空间）、**侧栏「删除对话」**（会话删除属执行轨）。唯一保留的写操作是**移除成员**与**转交负责人**（治理例外，服务端 `allowArchived`）。判定一律用服务端返回的 `status` 与 `currentUserRole`，不按创建者或姓名推断。
- 筛选请求失败时：清空上一个筛选的结果、显示错误态与「重试」，不得继续显示旧筛选的卡片。
- **归档语义（2026-09-11 确认：只读保留）**：归档后现任成员仍可按权限查看与下载，详情页只隐藏新增对话、续写、重试、上传等写入口，**不隐藏内容本身**；提示条文案为「该空间已归档，仅保留有权限的只读查看与下载」。恢复后写入口按当前权限重新出现。
- 转交/退出/归档均二次确认；退出与转交不可同时进行（唯一负责人不变量）。

### 2.9 团队动态（批次 3，仅预留位置）

- 右栏成员区之后预留「最近动态」摘要区（3 条）与「查看全部」抽屉入口；批次 3 前不渲染，不占位（方案 3.2：动态不占第四个主内容页签）。

## 3. 状态与反馈映射（方案 3.3 落地）

| 场景 | 呈现 |
| --- | --- |
| 加载 | 列表/弹窗内对应区域 `el-skeleton`；切页签不闪现「空间不存在」 |
| 空数据 | 两种区分（2.2 已列）；文件/成果/成员各有引导动作 |
| 错误 | 保留输入与已加载内容，`ElMessage.error`/行内错误说明失败对象、原因、重试方式（沿用 `notifyActionFailure` 文案模式） |
| 无权限 | 写操作不渲染；服务端不返回名称/摘要/数量/下载时，列表行显示「无权限查看」占位而非原始数据 |
| 不可用 | Agent 未加入/停用/能力未授权/Runtime 不可用/文件解析失败分别用 tooltip 或行内状态说明具体原因 |
| 成功 | 更新对应条目、计数与操作状态；历史列表在发送新消息后回到首位 |
| 归档 | 详情页提示条 + 隐藏新增/续写/上传动作（2.7 恢复入口） |

弹窗统一：现有表单与 footer 顺序（取消左、确认右）；删除/移除/转交/归档二次确认；所有字段有 label；图标按钮有 `aria-label`；支持键盘与焦点恢复。

## 4. 小屏与可访问性

- 断点沿用：1180px（右栏收起）、640px（页签收窄、文件行隐藏类型列）、520px（隐藏次要字段与计数徽标）。
- 成员管理/设置弹窗 ≤640px 用 `width="min(600px, calc(100vw - 32px))"` 规格自适应。
- 历史列表、成员列表均为按钮行，支持 Tab 与 Enter；角色下拉可键盘操作；弹窗关闭后焦点回到触发按钮。
- 状态点均有 `aria-label`（如「运行中」），不依赖颜色传达。

## 6. 已确认决策（2026-09-09，2026-09-11 修订）

1. 归档筛选采用「全部/活动/已归档」三段，默认全部；个人空间恒显（2.1）。
2. 历史列表直接展示「发起人」，不提供范围与发起人筛选（2.2）。
3. 成员管理弹窗采用同屏上下分段（员工/Agent），一次看清两类成员（2.6）。
