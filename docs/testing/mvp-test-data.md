# dsh-work MVP 统一测试数据说明

版本：V0.1
数据文件：`docs/testing/fixtures/mvp-fixtures.json`
用途：前端 Mock、服务端种子数据、接口契约测试和业务验收共用同一套语义。

## 1. 数据约束

- 全部为合成数据，不包含真实员工账号、客户、订单、合同、手机号、邮箱或密钥。
- 稳定 ID 不随构建变化，便于截图、接口测试与缺陷复现。
- 时间统一使用带时区 ISO 8601；金额同时记录币种。
- Mock 和真实 API 必须保持字段语义一致；切换真实 API 时不允许在页面组件内重写业务对象。
- 测试文件只保存元数据，不在仓库提交二进制附件或敏感内容。

## 3. 基准业务场景

### S-01 查询异常订单

- 操作人：林岚。
- Workspace：供应链经营分析。
- 输入：查询订单 `SO20260821001` 最新履约与缺料风险。
- 可用数据：订单、工单、库存和《供应链异常管理办法 V3.2》；通过预置连接器的 Mock 响应提供。
- 期望：生成带数据时间和来源的摘要；不得读取华南采购范围记录。

### S-02 上传文件并形成成果

- 操作人：林岚。
- 输入文件：`八月生产计划.xlsx` 元数据，对应 fixture 中 `file-production-plan`。
- 期望：上传鉴权和扫描通过，运行生成 `八月缺料风险分析.md` 成果 V1；Workspace 成员可见，外部成员不可见。

### S-03 取消与重试

- 操作人：林岚。
- 期望：运行中取消进入 `cancel_requested → cancelled`；重试产生新 Attempt，原事件完整保留；相同幂等键不重复启动。

### S-04 Agent 创建与发布

- 操作人：陈默。
- 输入：名称、说明、可选欢迎语、System Prompt、Skill、平台工具、可见角色和数据范围。
- 期望：负责人自动记录为陈默但创建页不显示负责人；配置不包含模型策略；先测试后发布。

### S-05 权限拒绝

- 操作人：赵宁。
- 尝试：打开 `ws-supply-analysis`、下载供应链成果、查询华东库存。
- 期望：服务端返回 `403`，前端不渲染写操作，审计记录对象、原因与 trace ID。

### S-06 运维治理

- 操作人：陈默和许宁。
- 期望：陈默可更新 Runtime 并发上限；许宁只能查看健康、Session 摘要、Token 和审计；二者默认均不可浏览完整消息正文。

## 4. 使用方式

1. 前端 Mock 适配器从 fixture 映射页面 ViewModel。
2. M2 数据库种子脚本读取相同稳定 ID，或提供一一对应映射表。
3. M3-M5 API 契约测试复用角色和对象 ID。
4. UAT 按 S-01 至 S-06 执行，并记录请求 ID、预期与实际结果。

当业务字段调整时，先更新契约和本说明，再更新 fixture、Mock 与服务端；不得只改单个页面。
