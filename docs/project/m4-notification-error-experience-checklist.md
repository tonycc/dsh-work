# M4-09 通知和错误体验验收清单

**状态：** 工程验收通过

**日期：** 2026-08-30

**范围：** 员工端运行失败、自动确认、连接器异常、上传/下载失败与统一 API 错误响应

## 完成定义

- [x] 失败的 Run 从当前 Attempt 读取持久化 `error_code`，员工端显示运行对象、原因、下一步和错误码。
- [x] 超时、连接器不可用、连接器超时、工具权限拒绝、模型失败和未知运行时错误均有独立安全文案。
- [x] 只有可重试错误展示“重新执行”；权限拒绝不诱导用户无意义重试。
- [x] 项目既定的“自动确认”策略在员工端明确展示，不提供只改变前端状态的伪审批按钮。
- [x] 成果下载先读取服务端 Blob，服务端失败时不再提示“已开始下载”。
- [x] 文件上传、对话创建、追问、重试和成果下载统一提供“对象、原因、下一步”，并在可用时展示链路编号。
- [x] 连接器单项与批量健康检查能指出异常连接器以及端点、凭据和 Runtime 的排查方向。
- [x] 管理端与员工端 API 客户端识别结构化错误；未知异常不向浏览器暴露服务端内部堆栈或敏感文本。
- [x] OpenAPI 错误契约要求 `code`、`message`、`object`、`suggestion` 和 `traceId`。

## 证据与验证

```bash
pnpm verify:m4:error
pnpm test:m4:error
pnpm test:m4:error:integration
pnpm typecheck
```

- `router-error-experience.test.ts`：覆盖超时、越权、输入错误、对象识别、下一步和内部异常脱敏。
- `m4-notification-error-experience.integration.test.ts`：使用真实 PostgreSQL Run/Attempt 验证错误码投影与可重试策略。
- `feedback.ts`：成果下载与通用员工操作失败的统一反馈入口。

## 明确边界

- 一期采用自动确认，不建设人工待审批队列；未来改为人工审批时必须增加服务端审批对象、决策接口、权限与审计，不能复用纯前端按钮。
- 当前错误分类以受控错误码和服务端异常为输入；生产级告警聚合、通知渠道、重试退避与值班升级属于 M5。
- 本清单证明错误链路的工程行为；R-15 默认模型回归已于 2026-08-30 通过独立真实探针和浏览器 UAT 关闭。

## 结论

M4-09 工程 Gate 关闭。员工和管理员在 MVP 的关键失败路径上能看到受影响对象、可理解原因和可执行下一步，且不会用成功提示掩盖服务端失败。
