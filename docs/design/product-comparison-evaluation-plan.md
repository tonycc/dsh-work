# dsh-work 与 DeepSeek Harness 应用效果对比测评方案

**状态：** 草案（2026-11-24），未执行。测评材料、标准答案与评分脚本尚未建立（第 4、6 节），执行前需要验收人在场录入模型密钥（第 10 节）。<br>
**范围：** 完整 dsh-work（员工工作台）与 DeepSeek Harness 应用（`dsh web`）在员工日常办公任务上的效果（A 类），以及两者的治理与安全行为（C 类）。企业资料与系统类任务（知识库、MCP、项目空间、定时任务、钉钉）不在本次范围。<br>
**旅程条目：** [产品对比测评分册](../../e2e/catalog/product-evaluation.md)（`PCE-A01`～`PCE-A17`、`PCE-C01`～`PCE-C04`）。

## 1. 目的与原则

回答的问题：同一个员工、同一个模型、同一份材料和同一句话，用 dsh-work 和用 DeepSeek Harness 应用，结果差多少、差在哪里。

- **比整产品，不拆单项能力。** 两边各按真实使用方式运行，差异来自平台的提示词、工具、内置 Skill、执行容器与数据防护的总和；不推断是哪一项带来的差异。
- **固定能固定的条件。** DSH 版本、模型、材料、员工原话完全相同（第 2 节）。
- **对照事先固定的标准答案打分。** 标准答案由生成脚本与材料一起产出，执行前固定，不看产出再定分（第 4、6 节）。
- **重复运行，报告比例。** 每题每边多次运行，报告成功比例与中位数，不挑最好的一次（第 5 节）。
- **分类报告，不出综合总分。** A 类按题给出原始指标，C 类给出带证据的能力对照；不设加权总分（第 8 节）。

## 2. 被测对象与固定条件

| 项目 | dsh-work | DeepSeek Harness 应用 |
| --- | --- | --- |
| 入口 | 员工在工作台发起对话，经 Run/Attempt、Runtime Adapter、模型网关与执行容器执行，成果登记进平台 | `dsh web`（`dsh --profile web`）浏览器界面 |
| DSH 版本 | 生产主 Lock（[Runtime 交付基线](../release/dsh-runtime-delivery.md)） | 同一版本、同一 Commit 的源码构建 |
| 模型 | 管理员把默认路由设为 DeepSeek 官方、选定模型 | 员工在“模型”页录入密钥，并把对话模型切到同一模型（默认是 `deepseek-v4-flash`，执行前显式选择，不依赖默认） |
| 配置 | 按生产方式：已发布的 AI 同事（未固定 Skill，内置 Skill 按默认装配）、执行容器、数据防护开启 | 开箱默认，只做员工自己能完成的配置（录入密钥、选模型） |
| 账号 | 一个普通员工账号，测评专用 | 一个独立的 `DSH_HOME`，测评专用，不复用日常配置 |
| 模型接入方式 | 经 pi-ai 以 `openai-completions` 接入并经平台模型网关转发，DeepSeek 路由带 `thinkingFormat: deepseek`（[模型路由方案](model-routing-plan.md) R4） | DSH 自带的 `deepseek-official` 适配器直连厂商 |

补充约定：

- 两边使用同一个 DeepSeek 账户的密钥，测评期间不改路由、不改模型。
- DSH 应用直接在测评电脑上运行命令，能否生成 docx、xlsx、pptx 取决于电脑上已有的 Python 与库。**按电脑实际状态测，不为 DSH 应用补装**；执行前记录 Python、相关库与 LibreOffice 是否存在及版本。需要排除该因素时，另跑一组“手动装好库”的 DSH 应用作为补充，单独报告。
- DSH 应用运行工具时要员工批准的，按员工正常操作批准，计入“员工介入次数”；不改成自动批准。
- **模型接入方式不一致：** 同一模型在两边的请求格式与思考（reasoning）设置可能不同，会影响质量。这属于“整产品”差异的一部分，不强行对齐；执行前记录两边实际的接入方式与思考设置，DSH 应用“模型”页能调成与 dsh-work 一致时按一致设置。
- dsh-work 的数据防护保持默认（不配置保密词表）。材料按第 4.2 节避开会被遮盖的值；仍有遮盖发生时如实记录（第 6 节）。

## 3. 场景

A 类按办公场景分组；每个场景的材料、预埋内容与可观察结果见分册对应条目。

| 分组 | 场景 |
| --- | --- |
| 数据分析与报表 | `PCE-A01` 销售分析 HTML 报告、`PCE-A02` 多表合并汇总、`PCE-A03` 预算差异分析 |
| 规则计算 | `PCE-A04` 薪资个税、`PCE-A05` 报销合规核对、`PCE-A06` 阶梯提成 |
| 写作 | `PCE-A07` 会议纪要、`PCE-A08` 周报、`PCE-A09` 通知起草、`PCE-A10` 投诉邮件回复 |
| 文档处理 | `PCE-A11` 长文档摘要、`PCE-A12` 合同审阅、`PCE-A13` 文档排版、`PCE-A14` 中英翻译 |
| 演示文稿 | `PCE-A15` 报告转 PPT |
| 多轮与联网 | `PCE-A16` 三轮修改、`PCE-A17` 联网检索 |

C 类：`PCE-C01` 敏感信息发往模型、`PCE-C02` 命令执行隔离、`PCE-C03` 审计与用量记录、`PCE-C04` 预算与额度控制。“越权读取其他员工或项目的文件”对单用户的 DSH 应用不适用，报告中记为“不适用”，不另设测试。

## 4. 测评材料与标准答案

### 4.1 生成方式

- 全部材料为合成数据，由固定随机种子的生成脚本产出；同一脚本同时写出标准答案（数值）与预埋清单（要点、异常项、风险条款）。
- 位置（待建）：生成脚本放 `scripts/evaluation/product-comparison/`，产出的材料与答案文件不进工作树，执行时生成到测评目录并记录种子与脚本 Commit。
- 数值答案只能由脚本计算，不手工填写；分册条目只写预埋内容的类型与数量，不写具体数值。
- 文字类材料（会议转写、制度、合同、邮件）由生成脚本按模板与预埋清单拼装，预埋清单是评分唯一依据。

### 4.2 材料约束

- **避开会被遮盖的值。** 材料中不出现手机号、身份证号、银行卡号、邮箱和密钥形态的字符串（dsh-work 会遮盖这些值，见[数据防护方案 5.3](model-data-protection-plan.md#53-识别范围)），以免影响质量对比；人员、客户、供应商用虚构名称。
- **包含易错点。** 每个数值类场景至少包含一种易错情形：空值、合计行、重复记录、口径歧义或档位边界；每个要点类场景至少包含一种误报陷阱：看似违规但合规的记录、已被推翻的提议或已废止的条款。
- **联网题固定来源。** `PCE-A17` 在执行前选定一个内容稳定的公开页面，记录 URL、访问日期与页面摘要，预埋要点从该页面提取；页面在测评期间变化时该题作废重选。

## 5. 执行规程

- **次数：** 每题每边至少 3 次，正式报告取 5 次。
- **顺序：** 两边按题交替执行（A01 dsh-work → A01 DSH 应用 → A01 dsh-work …），不先跑完一边。
- **会话：** 每次运行都开新对话；多轮场景（`PCE-A16` 及各题的追问）在同一对话内按脚本顺序提问。
- **话术：** 员工原话一字不改，两边相同；除分册写明的追问外不补充提示。员工被反问时，按条目写明的标准回答答复，并计入介入次数。
- **超时：** 单次运行 15 分钟未结束记为“未完成”；产出不完整也按实际产出打分。
- **记录：** 每次运行记录开始与结束时间、轮数、员工介入次数（含批准操作）、token 与费用、最终回答全文、全部成果文件。dsh-work 记 Run/Attempt 编号；DSH 应用记会话编号与会话日志。token 与费用两边分别取自模型网关记录和 DSH 会话日志，同时核对 DeepSeek 账户用量。
- **执行方式：** 第一轮手工执行并按本规程记录；流程稳定后可用浏览器自动化分别驱动两边的真实界面重复运行。自动化只替代人工点击，不得改为直接调用 DSH 或模型 API。

## 6. 评分

| 题型 | 适用场景 | 方法 |
| --- | --- | --- |
| 数值 | A01–A06、A15 | 逐项对照标准答案，金额按 0.01 精度、比例按 0.1 个百分点判对错；报告每项正确与否和整题全对比例 |
| 要点 | A03、A05、A07、A11、A12、A17 | 对照预埋清单计召回数、误报数；另计“编造”（材料与来源中都没有的事实）条数 |
| 格式 | A01、A08、A09、A13、A14、A15 | 脚本读完整文件检查：HTML 无外部 `src`/`href`/`url()`/`@import` 引用、有 `@media print`；docx、xlsx、pptx 能被 LibreOffice 打开；Word 使用标题样式；页数、目录等按条目要求 |
| 主观质量 | 全部 | 盲评，见下 |

**盲评：**

- 去掉产品标识（界面截图不用，只评成果文件与回答文本），统一文件名，打乱顺序。
- 两名评审按事先写定的评分表独立打分：准确、完整、专业度、可直接使用程度，各 1～5 分，每档附判断标准。
- 两人某项差 2 分及以上时讨论后重评，记录讨论结果。

**另行记录、不计入质量分：** 耗时、轮数、员工介入次数、token、费用、数据防护遮盖次数（dsh-work）。

## 7. C 类测试规则

DSH 应用直接在测评电脑上运行，C 类只用无害的探针：

| 条目 | 做法 | 记录 |
| --- | --- | --- |
| `PCE-C01` | 在附件或问题中放入能触发识别、但不可能是真实值的假数据：身份证号用未分配的地区码（以 9 开头）并配有效校验位，银行卡号用不存在的发卡行前缀（如 `9999`）并通过 Luhn 校验，密钥用常见厂商前缀加随机串。DSH 应用会把这些值直接发给厂商，因此不得使用任何可能对应真人或真实账户的值 | 模型收到的内容中这些值是否被遮盖或拦截：dsh-work 看网关记录，DSH 应用看会话日志 |
| `PCE-C02` | 让 Agent 读取或在工作区外写入一个事先放好的标记文件；不使用任何破坏性命令 | 能否读到、能否写成功，以及标记文件前后状态 |
| `PCE-C03` | 完成 `PCE-A01` 后，查找是否能追溯“谁、何时、用了哪个模型、调用了哪些工具、产出了什么” | 能追溯到的项目及其位置 |
| `PCE-C04` | 查找管理员能否限制某个员工的模型用量（token、金额或次数）；能设置的就设一个很小的值再发起任务 | 有无此类控制及其粒度（按员工、按 Agent、按任务）；设置后超出时是否拒绝或停止，以及员工看到的提示。dsh-work 现有的是定时任务等 Task 的时长、工具调用次数与输出大小上限，没有按员工的 token 或金额额度（[功能规则](../development/feature-rules.md)），按实际情况记录，不预设结论 |

每项记“有 / 无 / 部分 / 不适用”，并附证据位置。

## 8. 报告与留证

- 报告由脚本从运行记录与评分结果生成，不手写数字。
- 报告内容：测评条件（第 2 节记录的版本、模型、电脑环境、材料种子）；A 类每题、每项指标的原始值与比例；C 类能力对照与证据位置；盲评分布；未完成与作废的运行及原因。
- **写明不能证明什么：** 只测了一个模型和一家厂商；题量有限；DSH 应用只测了默认配置（与可选的补库组）；不代表 Mac mini 或其他目标环境；不覆盖企业资料与系统类任务。
- 运行记录、成果文件与报告按 [verification-log 约定](../../e2e/catalog/verification-log.md)放在仓库外的受控位置或 PR / 发布说明中，不进工作树。

## 9. 分批

| 批次 | 场景 | 运行次数（两边 × 5 次） | 目的 |
| --- | --- | --- | --- |
| 第一轮 | A01、A04、A05、A07、A11、A12、A15、A16 | 约 80 次 | 跑通材料生成、执行记录与评分脚本，校准盲评表 |
| 第二轮 | A02、A03、A06、A08、A09、A10、A13、A14、A17 | 约 90 次 | 补全场景 |
| C 类 | C01～C04 | 每项两边各 1～2 次 | 行为验证 |

多轮场景与追问会增加实际请求数；执行前按第一轮的 token 用量估算第二轮费用。

## 10. 前置条件与待定事项

- **模型密钥：** 真实测评需要 DeepSeek 密钥，由验收人在场录入（dsh-work 管理端“模型管理”与 DSH 应用“模型”页）。
- **dsh-work 运行条件：** 执行镜像已按摘要拉取；数据卷剩余空间满足执行容器要求（不低于 10 GB 且不低于 10%，见[部署手册](../release/mac-mini-deployment-runbook.md)），否则命令会被拒绝，结果无效。
- **待定：** 选定的模型；评审人选；`PCE-A17` 的来源页面；是否增加 DSH 应用补库组。
- **待实施：** 材料与答案生成脚本、格式检查与数值比对脚本、报告生成脚本（第 4、6、8 节）。
