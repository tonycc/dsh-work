## 1. 背景与目标

系统里的超时、并发、资源上限与保留期，大部分写死在代码里，少数在环境变量里，只有 Agent 运行限制、Runtime 容量与超时、钉钉参数可以在管理端修改。管理员遇到“运行总是超时”“磁盘余量不足拒绝执行”“知识库检索失败”时，既不知道当前生效的值，也不知道去哪里改。

目标：

> 2026-11-27 起按 RP11～RP15 调整为：全局参数集中在“安全与运维 › 平台配置”修改，由“平台配置”模块权限统一管理（安全类参数仍只限平台管理员）；Agent 运行限制与各类凭据留在原页面。下列第 1、2 条为 RP-S1 时的目标，保留作记录。

1. **能改的分散在各业务页面修改**，沿用该模块的权限与审计（RP11 起改为集中）；
2. **运维自己的参数集中在“运行参数”页面**，有运维查看权限即可查看，只有平台管理员能保存（RP10；RP12 起改为平台配置权限）；
3. **所有参数集中在一个只读总览查看**：当前值、来源（页面配置 / 默认值 / 环境变量 / 系统内置 / 部署脚本）、生效时机、去哪里改，以及每条运行链路实际生效的超时。

## 2. 边界

- **不开放安全隔离参数。** 执行容器（含在其中运行的 `python_execute`）与成果解析沙箱的内存、CPU、进程数、文件大小（`ulimit`）只读展示，不可修改（功能规则：执行前复核等安全约束不能豁免）。
- **不开放与 DSH 耦合的参数。** 模型重试策略（`MODEL_ROUTE_RETRY_POLICY`）、DSH 工具调用超时（patch 中 `toolCallTimeoutMs`）、平台工具契约超时、bash 默认超时不开放；调整须改代码并随 DSH 适配一起评审（AGENTS.md“Agent 执行统一使用 DSH”）。知识库检索超时的上限因此受工具超时约束（RP4）。
- **不开放实现细节。** 轮询间隔、心跳、宽限期、清理批量、缓存大小不进总览。
- **不开放上传与产物大小。** 产物、知识库文档、Skill 包的大小上限由前端校验、Schema、文本提取共用，单独可配会造成前后端不一致；总览只读展示。
- **启动参数不进页面。** 密码计算并发（环境变量，重启生效）、数据库连接池（代码固定 10）、会话密钥等只在启动时生效或涉及密钥；总览只展示非密钥项并写明修改方式。发布检查间隔是部署脚本写进 launchd 配置的变量，服务进程不读取，总览标注“改后重跑安装脚本”。
- **单进程部署。** 保存后刷新本进程缓存即生效；多实例同步不在本期。

### 4.2 已废弃但仍可能被误以为有效

- `DSH_WORK_EXECUTION_MAX_CONTAINERS`：已删除，启动时只打印警告（`attempt-execution-containers.ts:61`）。执行容器每个 Attempt 一个，并发由 Runtime 容量限制（`postgres-run-repository.ts:493`），后台车道合计最多到容量减 1。
- `DSH_WORK_DIRECTORY_SYNC_INTERVAL_SECONDS`：已忽略（`identity/config.ts:9`）。

总览不展示这两项。部署手册里关于它们的升级清理指引是有意保留的，不删；需要更新的是 [执行隔离方案](execution-isolation-plan.md)第 4.4 节仍写“Python 每次调用的容器仍占用全局槽位”的过时描述。

### 4.3 超时实际怎么生效

- 员工对话：`min(Agent 超时, Runtime 超时, 调用方上限)`（`attempt-dispatcher.ts:163`），不一致时静默取最小值，没有提示。自动任务与主动任务的调用方上限是任务预算里的 `timeoutSeconds`。
- 管理助手：`min(180 秒, Runtime 超时)`；会话摘要与项目档案员：`min(120 秒, Runtime 超时)`。
- Worker 启动准备最多 120 秒（`DEFAULT_SETUP_TIMEOUT_MS`），超时前运行尚未开始。
- 模型网关等响应头 120 秒；DSH 对超时、限流、服务端错误最多重试 2 次，最坏约 3 倍时长，仍受上面的运行超时截断。
- 知识库检索：一次检索串行两个 WeKnora 请求（检索、取文档），各受 10 秒检索超时；`knowledge_search` 工具契约固定 25 秒（须小于 DSH 默认 30 秒）。执行前检索带回退时最多 4 个请求。
- 网关与 WeKnora 客户端用 Node 全局 `fetch`，仓库内没有自定义 dispatcher，undici 默认等响应头 300 秒（依据 undici 文档默认值，未实测）。任何页面超时上限都不应超过 300 秒，除非实施时换 dispatcher。

### 4.4 发现的口径不一致

管理助手修改时的预校验比正式边界宽：

- Agent：超时 1～3600 秒、工具调用 1～10000 次、输出 1～10,000,000 字节（`admin-assistant-service.ts:534`），正式边界是 30～600 秒、1～100 次、1 KB～1 MB（`agent-spec.ts:54`）；
- Runtime：容量 1～1000（`admin-assistant-service.ts:495`），正式边界 1～128（`postgres-operations-service.ts:704`）。

确认卡片可能展示一个确认执行时才被拒绝的值。实施时改为共用正式边界。

### 4.5 读取时机

多数候选参数是模块级常量（如 `WORKSPACE_LIMITS`、`WEB_FETCH_MAX_PER_ATTEMPT`、`ERROR_RETENTION_DAYS`），或启动时读一次（`DSH_WORK_SESSION_TTL_SECONDS`）。改为可配置必须改成每次使用时读取，这是主要工作量。

## 5. 风险

| 风险 | 处理 |
| --- | --- |
| 调得过小导致大面积失败（例如检索超时 1 秒） | 每个参数登记最小值与最大值，服务端校验；页面显示默认值与“恢复默认” |
| 磁盘余量阈值调低后盘被写满 | 下限 2 GB；低于默认值时保存前二次确认 |
| 调高磁盘阈值会立即终止正在运行的命令 | 生效时机写明“立即（包括正在运行的命令）”；调高时确认，新阈值超过当前剩余空间时提示保存后会立即判定为磁盘不足 |
| 页面值与环境变量谁优先说不清 | 统一规则：页面保存过就以页面为准，环境变量只作初始值；超出页面范围或非整单位的初始值收进范围并在启动日志告警（同 DT30）；“恢复默认”回到系统默认，不回落到环境变量；总览“来源”列写明 |
| 超时层级不一致让人困惑 | RP7：保存时提示、总览显示实际生效值与起限制作用的一项 |
| 改了超时却被更低的固定上限截断 | 知识库检索上限 12 秒（工具 25 秒）；所有经 `fetch` 的超时上限 ≤300 秒 |
| 保留期缩短：通知立即从列表与未读数中消失，下次清理再删除 | 确认文案分开写“立即看不到”与“下次清理删除”；改大后未清理的通知会重新出现，同样提示 |
| 保留期缩短：错误记录与页面访问被删除 | 下限 90 天，保证“近 90 天”完整；缩短时提示“下次清理将删除早于 N 天的记录”并二次确认 |
| 读取网页上限在运行中途被改 | 上限在派发 Attempt 时固定，系统提示与复核用同一个值 |
| 总览泄露密钥 | 服务端按白名单返回，密钥类变量只返回“已配置 / 未配置” |

## 6. 方案

### 6.1 数据

新增迁移 `0136_platform_settings`：

| 列 | 说明 |
| --- | --- |
| `tenant_id`、`key` | 主键 |
| `value` | `jsonb` |
| `revision` | 乐观锁 |
| `updated_by`、`updated_at` | 最后修改人与时间 |

代码中的参数登记表（`domain/platform-settings.ts`）是唯一口径：键、所属模块、保存权限、类型、单位、默认值、最小值、最大值、生效时机、修改位置。服务端校验、总览接口、前端表单都从这里取，前端不另写常量。

模型路由首个响应超时随路由保存：迁移 `0137_model_route_headers_timeout`，`model_routes` 加 `headers_timeout_seconds`。派发时写入 Manifest 路由快照，网关令牌绑定的路由信息带上该值，网关按快照读取；旧 Manifest 没有该字段时按 120 秒，PF-04 恢复沿用原快照。

### 6.3 接口与权限

- `GET /api/admin/v1/runtime-parameters`：`ops` 查看权限。返回所有登记参数的当前值、默认值、来源、生效时机、修改位置、当前员工能否保存，以及“超时链路”。
- `PUT /api/admin/v1/platform-settings`：一次提交多项 `{ changes: [{ key, value, revision }] }`，同一事务逐项乐观锁（从未保存为 0），任何一项冲突整体返回 409；按登记表的保存权限判断（运维参数与登录会话有效期只限平台管理员，RP10）；恢复默认时保留该行、值存 JSON null、版本号继续递增（旧版本号不会再次生效）；第一次并发保存时后到者返回 409；值与当前生效值相同的项不写入、不记审计；逐项写审计 `platform.setting.update`（旧值 → 新值）。
- 两个路径都登记进 `admin-permissions.ts` 的路由对照，权限判断只在该判定模块内完成（功能规则第 13 节）：`runtime-parameters` 按 `ops` 查看；`platform-settings` 新增按键查登记表的规则，未登记的键默认拒绝。
- 业务页面（登录设置、知识库、模型路由）走各自已有或新增的模块接口，内部写同一张表或路由表。
- Agent 详情页显示“实际生效超时”需要读取 Runtime 超时，Runtimes 弹窗统计受影响 Agent 需要读取 Agent 超时：各新增一个只读选择器字段（同 `runtimes/builtin-tools` 的做法），登记进功能规则第 13 节。

### 6.4 管理端页面

导航“安全与运维”新增一项 **运行参数**（`/runtime-parameters`，`ops` 模块），两个标签：

1. **运维设置**：6.2 中保存权限为平台管理员的运维参数，分“磁盘与工作区”“并发与运行”“数据保留”三组；每项显示当前值、默认值、范围、生效时机，可编辑、恢复默认；保存时显示变更摘要并二次确认危险项。非平台管理员只读，保存按钮停用并说明原因。
2. **参数总览**（只读）：
   - 顶部“超时链路”卡片，各自显示实际生效值和起限制作用的一项，有不一致时标黄并说明：
     - 员工对话：Runtime 超时上限，以及运行超时超过它的已发布 Agent 数量（例如“2 个 Agent 被截断到 3 分钟”）；
     - 自动任务与主动任务：`min(Agent, Runtime, 任务预算)`，同样列出被截断的数量；
     - 管理助手（内置 180 秒）、会话摘要与项目档案员（内置 120 秒）、发布试运行；
     - 模型请求（路由首个响应超时、重试次数）；
     - 知识库检索（检索超时 × 2 个请求与工具 25 秒）。
   - 下方按模块分组的表格：参数、当前值、来源、生效时机、修改位置（能保存时为链接，否则显示“需要平台管理员”或“需要某某修改权限”）；
   - 支持按来源筛选与搜索。

业务页面：

- **员工与权限**：新增“登录设置”卡片（会话有效期），只有平台管理员能保存。
- **企业知识库**：在现有的连接配置中增加检索超时与上传下载超时；检索超时旁说明两个请求与工具 25 秒的关系。
- **模型治理 → 路由编辑**：新增“首个响应超时”，说明只影响之后新建的运行。
- **Agent 详情 → 能力** 与 **Runtimes 配置弹窗**：运行超时旁显示实际生效值，Agent 超时大于 Runtime 超时时提示（RP7）。

### 6.5 RP-S1 与本方案不同之处

- 保存接口一次提交多项（6.3），页面一次确认不拆成多次非原子写入。
- 知识库连接已在“企业知识库”页配置，RP4 的两个超时并入该页现有连接配置（RP-S2）。
- Agent 能力页、Runtimes 页的文案改为“由平台管理员在‘运行参数’中设定”，不直接显示当前值：直接显示需要 Agent、连接器模块管理员跨模块读取运维参数，暂不新增这类读取。
- 超时链路暂未包含“发布试运行”，“自动任务与主动任务”暂不统计被截断的任务数（需要跨表汇总任务预算），随 RP-S2 补充。
- 接口额外返回数据盘当前剩余空间（`disk`），供页面在调高磁盘阈值前提示。

### 6.6 集中到平台配置（RP11～RP15，2026-11-27）

**页面：** “安全与运维 › 平台配置”（`/platform-config`，模块 `config`），替代“运行参数”。两个标签沿用：

1. **配置**：按组列出全部集中参数，每项显示当前值、默认值、范围、生效时机、来源与保存权限。组：
   - 磁盘与工作区、并发与运行、数据保留（RP-S1 的 8 项）；
   - Runtime：每个 Runtime 一行，容量（1～128）与单次执行超时（1～60 分钟）；
   - 登录与钉钉：登录会话有效期（1～168 小时）、钉钉会话有效期、待绑定凭证有效期、每日代绑上限、钉钉接口超时；
   - 外部服务：知识库检索超时（3～12 秒）、上传与下载超时（30～300 秒）、模型首个响应超时（30～300 秒）。
   只限平台管理员保存的项标“只有平台管理员能保存”；钉钉应用未配置时钉钉参数只读并说明原因。
2. **总览**：沿用 RP-S1 的超时链路与全部参数表（含只读项、Agent 运行限制的跳转），按 `admin:config:read` 查看。

**存储：** 登记表为每项增加“存储位置”，集中页面只做读写入口，数据不搬家，读取方不改：

| 参数 | 存储 | 说明 |
| --- | --- | --- |
| RP-S1 的 8 项、登录会话有效期、知识库两个超时、模型首个响应超时 | `platform_settings` | 登录会话有效期：页面从未保存时以环境变量 `DSH_WORK_SESSION_TTL_SECONDS` 为初始值（超出范围或非整小时收进范围并告警，同 DT30）；只影响之后的登录。知识库与模型超时改为每次请求时读取 |
| Runtime 容量与单次执行超时 | `runtime_configurations` | 写入时以当前修订为基础新建一条修订，只改这两个字段，调度状态、停用工具与停用内置 Skill 原样保留；乐观锁用该 Runtime 的修订号 |
| 钉钉四项 | `dingtalk_app_configurations` | 只更新这四列，不重新校验凭据（凭据保存仍在钉钉集成页，只限平台管理员）；该表没有修订号，乐观锁用 `updated_at`（读取时返回、保存时比对） |

**权限（RP12）：**

- 新增模块 `config`（标签“平台配置”），`admin:config:read` / `admin:config:write`；`admin:read` / `admin:write` 照常覆盖全部模块，现有全模块角色自动获得。只有 `admin:ops:read` 的角色不再能看到该页（RP-S1 页面尚未部署到生产，影响限于本机）。
- 路由对照：`platform-config`（读）按 `config` 查看；`platform-settings`（写）按 `config` 修改，服务层事务内按每项保存权限复核：`platform-admin` 项只认本地授予的 `admin:*`，其余认 `admin:config:write`（同 `requireAdminModuleActor`）。
- 管理助手的 `runtime-update-configuration`：修改容量或超时时按 `config` 修改权限判定，修改调度状态与停用工具仍按 `connector`；同一计划同时改两类时两项权限都要。
- Runtimes 页、钉钉集成页、企业知识库页移除这些参数的显示与编辑（RP14），原接口中这些字段的写入移除或改为拒绝，避免两处可写。

**模型首个响应超时（RP13）：** 网关每次请求读取当前值；不新增 `model_routes` 列，不改 Manifest 路由快照。正在进行的运行中，下一次模型请求即按新值。

## 8. 验收

- **单元：** 登记表校验（范围、类型、保存权限）、超时链路计算、保留期清理与通知过滤按配置值、环境变量初始值收进范围。
