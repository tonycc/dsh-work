## 1. 背景与目标

协作模式（B）已有窄屏布局（820px 以下底部标签栏 + “列表 → 聊天”两级），也有 H5 接入规范，但移动协同仍不可用，原因有两个：

- **收不到提醒。** 通知仅站内（功能规则 3.7），员工不打开网页就不知道有人 @ 了自己、任务完成或需要处理；
- **手机打不开。** 部署为内网 IP + 自签根证书，部署手册禁止公网转发，手机走蜂窝网络无法访问。

目标：员工在钉钉里及时收到与自己相关的提醒，点开后在钉钉内直接进入对应页面继续协作；平台的身份、权限、业务状态与 Agent 执行链路保持不变。

## 3. 边界

- **钉钉只是渠道，不是执行器。** 任何从钉钉发起的 Agent 交互都必须创建 Session/Run，经 Run/Attempt → Runtime Adapter → DSH 执行；钉钉适配层不调用模型、不实现工具循环（[AGENTS.md](../../AGENTS.md)）。
- **权限仍由平台裁决。** 推送前、点击后都按现行规则检查可见权限；钉钉侧的群、部门或角色不授予任何平台权限。
- **管理端不上公网。** 公网入口只暴露员工端的页面、`/api/workbench/v1` 与 `/auth/workbench`；管理端（4180）、服务端口与数据库保持内网。
- **不改桌面端登录。** 账号密码与 AI Hub 登录保持原样；钉钉免登只在钉钉客户端内生效（4.3）。
- **不做群机器人 Webhook 推送。** 群 Webhook 无法按人做权限检查，所有提醒发给具体员工本人。

## 4. 分阶段方案

### 4.1 钉钉工作通知

**触发事件（首批）：**

首批事件即以下五类站内通知（`user_notifications.kind`，站内部分 2026-10-31 已实现），钉钉只是它们的投递渠道。被加入项目、Skill 审核结论与长时间 Run 完成不推送钉钉（DT16）。

| 事件 | 接收人 | 站内通知类型 |
| --- | --- | --- |
| 项目任务指派给我 / 改派给我 | 被指派员工 | `task_assigned` |
| 我创建的项目任务被他人完成 | 任务创建人 | `task_completed` |
| 我的定时任务一次执行没有成功（失败、跳过、错过、未能开始） | 任务所有者 | `automation_failed`；成功不通知（站内通知方案 NC6） |
| 我设置的项目 Agent 任务定时执行被暂停或停止 | 规则设置人 | `task_schedule_stopped` |
| 对话或讨论中 @ 我 | 被 @ 的员工 | `mention` |

**消息内容：** 使用钉钉工作通知的卡片或链接消息，文案与站内通知一致，只放“谁、在哪个项目/对话、做了什么”和一个跳转链接，例如“张三在『Q4 投放复盘』给你指派了任务『整理渠道数据』”（任务标题按 DT17 显示，超长截断；定时任务名称在 `automation_failed`、`task_schedule_stopped` 中按任务标题同等处理，见 8.8）。不放消息正文、Agent 回复、文件名与文件内容、成果摘要和对话标题。绑定确认用的一次性验证码（4.2）是工作通知中唯一的另一类内容，只含验证码与用途说明。名称在发送时按接收人当前可见性读取，不使用事件发生时的快照。

**投递链路：**

1. 业务事务内已写入站内通知 `user_notifications`（站内通知方案，已实现）；同一事务为已绑定且未关闭该类型的接收人写入投递记录 `external_notification_deliveries`（来源为通知 ID），状态 `pending`。不另建事件判断；
2. 单进程投递器（与定时任务一致，单一所有者）领取 `pending` 记录，**发送前复核**：接收人账号有效、仍有对象可见权限、未关闭该类事件、绑定有效，任务类事件还要求未静音该空间（`mention` 与站内一致，不受按空间静音影响，功能规则 3.7）；任一不满足记为 `skipped` 并写原因；
3. 调用钉钉工作通知接口发送，成功记 `sent` 并保存钉钉任务 ID；可重试错误按退避重试，超过上限记 `failed`（死信），不再重试；
4. 投递失败不影响业务结果，也不回滚站内通知（沿用 3.7“通知失败不把已成功的业务变更报成失败”）。

去重键为 `(tenant_id, channel, recipient_user_id, notification_id)`，重放与重启不会重复发送。同一接收人短时间内的同类事件可合并为一条（例如 5 分钟内 3 个任务被指派给你），合并窗口为可配置项。

**与站内通知清扫的关系：** 站内通知每天删除 90 天前的记录（站内通知方案 NC-S4）。投递记录只保存通知 ID，**不对 `user_notifications` 设外键**，不随通知级联删除，自有保留期（建议 180 天，留作送达证据）；清扫跳过仍有 `pending` 投递记录的通知，投递器在通知已被删除时把投递记为 `skipped`（原因：通知已过期）。P1 验收覆盖这一点。

**员工偏好：** 员工端个人设置增加“钉钉通知”开关与事件类型选择，默认开启首批事件；沿用按空间静音，静音的空间不推送任务类事件，@ 我照常推送，只能按事件类型关闭。

**站内跳转：** 公网入口就绪前，链接指向内网员工端地址并注明“需在公司网络内打开”（DT15）；链接基址为配置项，公网入口上线后改为公网地址。链接指向稳定路由（项目空间方案已规定链接与 A/B 模式无关），在钉钉内打开时走 4.3 免登；在系统浏览器打开时走现有登录。

### 4.2 账号匹配（手机号）

**现状：** `users` 表没有手机号字段；AI Hub 目录同步只带 `email`（AI Hub 登录计划删除，组织架构方案 OD1）；独立账号的登录标识可以是手机号，但它是登录名，不是经过核对的联系方式。

**方案：**

- `users` 新增 `mobile`（E.164 规范化存储，唯一约束为 `(tenant_id, mobile)`，允许为空）。来源为管理端“员工与权限”由管理员维护或批量导入。**员工不能自助修改手机号。**
- 匹配：管理员触发或定时任务调用钉钉“根据手机号查询用户”接口，得到钉钉 `userid`，写入 `external_account_bindings`（`channel = dingtalk`、`user_id`、`external_user_id`、`external_union_id`、`matched_mobile`、`status`、`matched_at`、`confirmed_at`），两侧各自唯一。
- 绑定分两级：
  - **已匹配：** 手机号查到唯一钉钉用户即可接收工作通知；
  - **已确认：** 员工在桌面端员工设置中点击“绑定钉钉”，服务端经工作通知向已匹配的钉钉用户发送一次性验证码（短时有效、限次尝试），员工在桌面端输入后确认。该过程同时证明平台身份（已登录桌面端）与钉钉身份（收到验证码），不依赖公网登录。只有已确认的绑定才允许免登（4.3）。
- 失效：平台手机号变更、账号停用、钉钉侧查不到该手机号（离职后接口不再返回）或返回的 `userid` 变化时，绑定置为失效，停止推送并要求重新确认；每次变更写审计。
- 冲突：同一手机号对应多个平台账号（唯一约束阻止写入）或钉钉返回异常时不绑定，在管理端列出待处理项。

**为什么要“已确认”：** 手机号录错时，已匹配只会让对方收到少量名称级提醒；若直接允许免登，录错就等于把整个账号交给他人。

### 4.3 钉钉工作台入口与免登（后置，DT7）

- **公网入口：** 员工端使用独立域名（例如 `m.<企业域名>`）+ 受信证书，经反向代理只转发员工端页面、`/api/workbench/`、`/auth/workbench/`；按[移动端接入规范](../development/mobile-integration-guide.md) §2 把该 origin 加入 `DSH_WORK_WORKBENCH_ORIGINS`。`server/src/modules/identity/config.ts` 只在 AI Hub OIDC 模式下要求所有 origin 与 `DSH_WORK_WORKBENCH_PORT` 同端口；账号密码模式（`localAudienceConfiguration`）不校验端口，公网入口用 443 可以正常启动。AI Hub 登录计划删除（OD1），无需为此放宽端口校验。公网暴露前补充登录限流核对、访问日志与告警，是否加 WAF 或网关白名单由部署方决定。
- **钉钉应用：** 在钉钉开放平台创建企业内部应用，配置 H5 微应用首页为公网入口的协作模式（B）首页，并申请通讯录手机号查询、工作通知、免登等最小权限。
- **免登：** 页面在钉钉容器内用 JSAPI 获取一次性授权码 → 新增 `POST /auth/workbench/dingtalk/login`，服务端用授权码换取钉钉 `userid` → 查已确认绑定 → 签发员工端 Session Cookie（会话来源见下条）。绑定未确认时提示先在桌面端完成 4.2 的确认（独立账号员工也可在钉钉内直接用账号密码登录）；不存在绑定时提示联系管理员，不自动建账号。
- **身份语义：** 免登签发的是同一平台账号的会话，不新增账号类型，但新增会话来源 `dingtalk`：迁移 0077 的 `authentication_provider` 约束目前只允许 `ai-hub-oidc` 与 `local-password`，`local-auth-service.ts` 的会话校验写死 `local-password` 且要求账号有密码凭据，需新增迁移并调整校验，使 `dingtalk` 会话不要求密码凭据、但要求绑定仍为已确认（与[组织架构方案](org-structure-plan.md)附录 A 的结论一致，届时共用）。不采用“以 `local-password` 签发、只在审计中记录钉钉”的做法，以免会话来源失真。登录方式写入审计；收权、停用、Session 撤销沿用现有机制，绑定失效时撤销该账号的 `dingtalk` 会话。
- **移动端规范调整：** 现行规范写明“认证优先使用平台独立账号、不集成 AI Hub”。钉钉免登作为钉钉容器内的附加方式写入该规范，规范的其余约束不变。

### 4.4 钉钉机器人对话（Stream）

员工在钉钉里给企业的机器人发单聊消息，与 AI 同事对话。接入采用钉钉 Stream 模式：服务端主动建立出站长连接，不需要公网回调地址，因此不依赖 4.3 的公网入口（DT7）。入口、身份、权限与披露策略按 [Agent 全生命周期模板](../development/agent-lifecycle-template.md)另行记录。

**执行链路不变。** 钉钉适配层只做“收消息 → 识别员工与目标 Agent → 写入对话消息并创建 Run → 把结果发回钉钉”；Run 经 Run/Attempt → Runtime Adapter → DSH 执行，与桌面端发消息走同一个业务入口。适配层不调用模型、不实现工具循环；DSH 不可用时回复“暂时无法处理”，不降级。

**入站处理：**

1. Stream 连接由单进程持有（与投递器一致，单一所有者），断线自动重连；
2. 按钉钉消息 ID 去重（Stream 至少投递一次），重复消息直接确认、不再处理；
3. 按发送人钉钉 `userid` 查**已确认**的绑定（4.2）。只匹配未确认时回复“请先在桌面端完成钉钉绑定”；没有绑定时回复“请联系管理员”；账号停用或绑定失效同样拒绝；
4. 确定目标 Agent（下文“切换”），并检查该员工当前仍可见、可使用该 Agent，且该 Agent 已开启钉钉对话（DT9）；
5. 找到该员工与该 Agent 进行中的钉钉对话（DT10）；钉钉对话一律是员工**个人空间**的对话，不进入项目空间、群组或任务对话。该对话固定的 Agent 版本与当前发布版本不同、或 Agent 已不可用时，与功能规则 2.2a 一致新建对话，不续用旧对话；没有进行中的对话也新建；消息写入对话并标注来源 `dingtalk`（DT12），随后创建 Run；
6. 同一对话已有排队、运行中或等待确认的 Run 时，新消息拒收，回复“上一条还在处理，完成后再发”，不写入对话（DT14）。现有空闲会话检查 `requireIdleSession`（判定在 `server/src/modules/run/postgres-run-repository.ts`，统计排队、运行中、等待、请求取消的 Run）目前只在项目任务对话时由 `run-orchestration-service.ts` 传入，个人对话走不到；钉钉入口需要新增显式开启该检查的参数，把冲突（409 `stateConflict`）映射为上述回复，并以钉钉消息 ID 作为 Run 的幂等键，使重投消息不重复建 Run。Run 停在等待确认时新消息同样被拒，员工可发“新对话”另起对话。

**切换与指令：** 首版只支持少量文本指令：“帮助”、“切换”（返回可选 AI 同事列表，只列该员工可见且已开启钉钉对话的 Agent）、“切换 <名称>”、“新对话”（结束当前钉钉对话，下次消息新建）。没有切换过时使用管理员指定的机器人默认 Agent（DT13）；未指定、该 Agent 已关闭钉钉对话或员工不可见时，回复可选 AI 同事列表。员工端目前没有面向员工的“通用助手”，不能假定存在。

**回复形式（DT19）：** 入站消息受理后立即回复“<Agent 名>正在处理”；Run 结束后对最终回复整体做下列复核，再以普通消息发出。首版不用流式卡片，避免生成中途内容已外发。

**知识库（DT18）：** 钉钉中不能添加知识库；同一对话在桌面端已添加的知识库，钉钉发起的 Run 照常检索（仍按员工与 Agent 的知识库可见范围）；新建的钉钉对话没有知识库。

**开关的性质：** “允许在钉钉中对话”与机器人默认 Agent 属于 Agent 与租户的访问设置，与可见角色一样保存后立即生效、写审计，不属于 Agent 版本，不作废验证证据（与功能规则“Agent 岗位权限”一节“三个问题”同类处理）。

**出站内容（DT9）：**

- 只发送 Agent 最终回复的文字（必要时分条，超长截断并提示到桌面端看全文）；不发送思考过程、工具调用明细、知识库原文；回复末尾的“参考来源”（功能规则第 11 节）不外发文档名，改为“引用了 N 份知识库资料，请到桌面端查看”，知识库不可用的提示照常外发；
- Run 生成的文件和成果不发送，只说明“已生成 N 个文件，请到桌面端查看”；
- 发送前复核：账号有效且绑定仍为已确认时，若员工已不可见该 Agent 或 Agent 已关闭钉钉对话，只发送“结果请到桌面端查看”；账号停用或绑定失效时**不发送任何内容**（该钉钉 `userid` 可能已不属于本人），只记投递为 `skipped`；
- 每次出站写入投递记录（来源为 Run 与消息 ID、长度与内容摘要哈希，不另存正文），作为外发审计证据。

**需要确认的动作（DT11）：** Run 进入等待员工确认（工具审批、安装 Skill 等）时，钉钉侧回复“需要你在桌面端确认后继续”，不提供按钉钉内确认的入口。员工在桌面端处理后，该 Run 的最终结果仍发回钉钉（Run 记录发起渠道）。员工在钉钉里发图片或文件时，首版回复“请到桌面端上传”，不接收附件。

**桌面端表现（DT12）：** 钉钉对话就是平台里的普通对话，出现在历史对话中，桌面端可以继续；桌面端追加的消息与回复**不**推送到钉钉，只有钉钉发起的 Run 回复钉钉。

**DSH 不可用：** 回复“暂时无法处理，请稍后再试”，不降级为其他执行方式。

**不做：** 群聊 @ 机器人（群成员与平台权限不一致）、钉钉内确认动作、附件收发、一个 Agent 一个机器人。

## 5. 数据与接口草案

| 对象 | 说明 |
| --- | --- |
| `users.mobile` | 管理员维护的手机号，E.164，租户内唯一 |
| `external_account_bindings` | 平台账号与外部渠道用户绑定（`channel`，钉钉为 `dingtalk`；外部 `user_id`、`union_id`），状态：已匹配 / 已确认 / 失效（DT5，取代原草案的 `dingtalk_user_bindings`） |

| 消息来源 | 对话消息增加来源标注（`dingtalk`），桌面端展示 |
| `external_notification_deliveries` | 投递记录：来源通知 ID（`user_notifications.id`）或机器人回复的 Run/消息 ID、接收人、渠道、状态（pending / sent / skipped / failed）、尝试次数、下次尝试时间、跳过或失败原因、钉钉任务 ID |
| `user_notification_preferences` | 员工渠道开关与事件类型选择 |
| `POST /auth/workbench/dingtalk/login` | 钉钉容器内免登；会话来源 `dingtalk`（新迁移放宽 0077 约束） |
| 管理端“钉钉集成”页 | 应用凭据状态、匹配进度、待处理冲突、投递失败列表 |

## 8. 待评审确认的默认值与风险

1. **钉钉接口与配额：** 根据手机号查询用户只能查到在职员工；工作通知有每人每天条数与同内容去重限制。具体接口路径、权限点、限频与配额在 DT-S1 开始前按钉钉开放平台最新文档核对，并据此确定合并窗口和每人每日上限。
2. **服务器出站：** 投递器与 Stream 连接需要访问钉钉开放平台；若内网有出站白名单，需放行对应域名。
3. **公网暴露的安全基线：** 员工端上公网后登录接口暴露在外，需确认限流阈值、是否要求钉钉内访问以外的来源也能登录、是否加 IP 或网关控制。
4. **Run 完成提醒：** 桌面端发起的长时间 Run 完成不推送钉钉（DT16）；钉钉发起的 Run 由机器人直接回复（4.4）。
5. **手机号来源：** 首次启用需要管理员批量导入手机号；导入错误的影响由 4.2 的两级绑定控制。
6. **机器人回复是外发正文：** DT9 允许已开启的 Agent 回复完整文字，这些内容会存放在钉钉侧且无法收回。管理员开启前应确认该 Agent 的知识库、Skill 与工具不会产出不宜外发的内容；开关变更写审计。
7. **Stream 单连接：** 多实例部署时只能有一个进程持有 Stream 连接，需要与定时任务一致的单一所有者机制。
8. **任务标题外发：** 按 DT17 显示任务标题，标题中的业务内容会随工作通知外发，需在功能规则 3.7 中写明，员工端创建任务处无需额外提示。定时任务名称（失败与暂停通知）评审默认按任务标题同等显示，评审时确认。

## 9. 验收

- **P0：** 冒烟服务提供测试身份与内存数据，钉钉渠道使用测试替身，验证员工通知设置页面与管理端集成页可用；
- **P1：** 专用 PostgreSQL + 钉钉渠道测试替身（入站 Stream 消息由替身注入，Run 经受控 Runtime），覆盖机器人入站去重（同一消息不重复建 Run）、未确认绑定被拒、未开启钉钉的 Agent 不可切换、默认 Agent 未指定或不可见时回复可选列表、处理中新消息被拒且“新对话”可另起、Agent 版本变化后新建对话、钉钉消息在桌面端可见并标注来源、等待确认时提示到桌面端且处理后结果回到钉钉、文件与参考来源文档名不外发、超长回复截断、出站复核（收权或关闭开关后只发提示，绑定失效后不发送）、DSH 不可用时回复“暂时无法处理”；以及投递去重、发送前复核（收权后不推送）、按空间静音不推送任务类事件但 @ 我照常推送、DT16 之外的通知类型不推送、失败不影响业务、绑定失效与重新确认、站内通知清扫不删有待投递记录的通知且投递记录不随之消失。免登拒绝未确认绑定与 `dingtalk` 会话校验随 DT-S4 验收；
- **P2：** 真实钉钉企业内部应用、真实手机号匹配、真实工作通知送达、真实 Stream 机器人对话（经真实 DSH）与钉钉内免登跳转（DT-S4），按发布流程留证。测试替身与 P0/P1 绿灯不能代替 P2。
