# 发往模型的数据防护方案

**状态：** 决策已确认，尚未实施。本文所述能力在实施并通过第 9 节验收前均不可用。<br>
**更新日期：** 2026-11-06（5.4 补充已识别值全文遮盖、Attempt 内已识别值集合与思考块签名稳定性）<br>
**依据：** 当前 Model 模块、Runtime Adapter 与 [模型路由方案](model-routing-plan.md)；参考开源项目 [yetone/magpie](https://github.com/yetone/magpie)（MIT）的网关脱敏设计（`internal/redact`、`internal/gateway/masked.go`），只借鉴设计，不复制代码。<br>
**关联：** [模型路由方案](model-routing-plan.md) 第 7 节（本方案将其提前立项）、[执行隔离方案](execution-isolation-plan.md) 第 10 节、[WeKnora 接入方案](weknora-knowledge-plan.md)。

## 1. 背景与目标

员工使用 Agent 时，公司的隐私与机密信息会随请求发给外部模型厂商：员工输入、上传与工作区文件、知识库检索结果、MCP 与工具返回、Python 执行输出、群组与项目空间的历史消息。后几类由 DSH 在 Agent Loop 中直接拼进上下文，平台在 Run 入口或 Adapter 事件处都看不到。

目标：**发往外部模型厂商的请求中不出现密钥，个人信息与企业机密词以占位符代替**，且不影响员工正常使用。

- 识别出的值在请求中替换为占位符，厂商回复（含流式与工具调用参数）中的占位符还原为原值，DSH 与员工看到的始终是原值；
- 密钥命中时请求不发出，本轮明确失败；
- 每个请求的处理结果可审计，审计中不出现原值；
- 策略按 Provider 信任级别区分，策略版本随 Attempt 固定。

## 2. 已确认决策（2026-11-05）

| 编号 | 决策 |
| --- | --- |
| D1 | 模型网关从模型路由方案第 7 节**提前立项**，作为数据防护的前提。网关只做认证、转发、计量与数据防护，不承担任何 Agent 执行逻辑 |
| D2 | WeKnora 改用**内网部署的嵌入模型**，知识库文档不出内网，不经网关脱敏（另立事项，见 6.3） |
| D3 | 企业词表第一期由**管理员手工维护**（CSV 导入、检测试用、单独授权查看与编辑），不做自动同步 |
| D4 | Provider 信任级别只分两级：**内部部署 / 外部厂商**，不区分境内与境外 |
| D5 | 外部厂商：**密钥拦截**，个人信息与企业词表**遮盖**；内部部署：不处理 |
| D6 | 图片与扫描件：外部厂商**放行并记录**，第一期不拦截、不做 OCR；内部部署放行 |
| D7 | 员工端：**遮盖不提示**；拦截时说明被拦截的**类别**，不显示具体值 |
| D8 | 审计只记录类别、次数、处理方式、策略版本，**不保存原值，也不保存原值的哈希或上下文** |
| D9 | DSH 内置的 `deepseek-official` 路由若不能指向网关，改为以 `openai-completions` 经 pi-ai 接入 DeepSeek；**任何路由都不允许绕过网关** |

## 3. 边界

- **不是内容合规审核。** 本方案不判断输入或输出是否违规，也不拦截模型展示给员工的内容。
- **执行职责不变。** 模型调用仍由 DSH 发起；网关是请求转发路径上的平台组件，不运行模型循环、不改写对话结构、不做协议互转（[AGENTS.md](../../AGENTS.md)、[总览 3.5](../development/overview.md#35-agent-执行引擎统一)）。
- **识别不调用模型。** 第一期只用规则与词表，不在平台侧调用 LLM 做识别；本地 NER 模型留待评估（第 8 节）。
- **不做 Attempt 内路由切换。** 网关只转发到本 Attempt 路由快照中的模型，延续模型路由方案 2 与 4.7 的失败语义。
- **内部部署模型不处理。** 数据不出企业网络，脱敏只会损失回答质量（D5）。
- **图片不识别。** 文本规则无法覆盖图片与扫描件，第一期只记录（D6）。

## 4. 现状与缺口

| 发往模型的路径 | 现状 | 本方案处理 |
| --- | --- | --- |
| DSH → `deepseek-official`（`dsh-llm-deepseek` 适配器） | DSH 直连厂商，凭据在 `DSH_HOME` | 改指向网关；不能改则按 D9 改走 pi-ai |
| DSH → pi-ai 路由（模型路由方案 4.3） | 方案未实施 | `baseURL` 指向网关，`apiKeyEnv` 为 Attempt 短期令牌 |
| WeKnora → 在线嵌入模型 | 文档全文发往在线服务 | 改内网嵌入模型（D2） |
| 其他直接调用模型的组件 | 未盘点 | DLP-S0 盘点；发现即纳入网关或改内网 |

## 5. 方案

### 5.1 执行链路

```text
Attempt Dispatcher ── 路由快照（含 trust_level、策略版本）── Manifest
        │
Runtime Adapter ── 签发 Attempt 短期令牌 ── 生成 patch：baseURL=网关，apiKeyEnv=令牌变量
        ▼
DSH Worker ──请求──> 模型网关
  1. 校验令牌：租户、Run、Attempt、路由与模型必须一致，过期或越权即拒绝
  2. 按快照中的策略版本识别敏感值：
       内部部署 → 原样转发
       外部厂商 → 密钥命中则拦截；个人信息与企业词表替换为占位符
  3. 用平台保存的厂商密钥转发；记录用量与数据防护审计
厂商回复（流式） ──> 网关还原占位符 ──> DSH
```

### 5.2 模型网关（最小范围）

- **形态：** 第一期作为现有 Node.js 模块化单体中的独立模块与独立监听端口，只对本机或执行网络开放；是否拆为独立进程按容量与故障域证据另行评审（[总览第 11 节](../development/overview.md#11-生产演进原则)）。
- **令牌：** Adapter 为每个 Attempt 签发短期令牌，绑定租户、Run、Attempt、路由与模型，Attempt 终态即失效。DSH 只持有该令牌，不再持有厂商密钥。
- **厂商密钥：** 由平台使用环境主密钥加密保存（沿用 MCP Bearer Token 的做法，[总览第 9 节](../development/overview.md#9-身份安全与数据边界)），明文只在网关转发时解析，不进入 Manifest、patch、日志或 API 响应。`dsh-managed` 凭据后端随之退役。
- **只转发、不改造：** 网关保持厂商协议原样，只替换文本内容中的敏感值；不做协议互转、不做回退、不做重试放大（重试策略沿用模型路由方案 4.3 的显式 `retryPolicy`）。
- **计量：** 网关按请求记录 token 用量，与 DSH 会话日志的用量核对；`effective_model` 以网关实际转发的模型为准。

### 5.3 识别范围

| 类别 | 内容 | 识别方式 |
| --- | --- | --- |
| 密钥（`secret`） | 常见厂商 API Key 前缀、私钥块、JWT、Bearer Token、连接串与配置中的密码，以及“密码为 / 密钥是 / token:”等中英文字段表述 | 前缀与结构规则、字段名上下文 |
| 个人信息（`personal`） | 手机号、身份证号（校验位）、银行卡号（Luhn 校验）、邮箱 | 规则加校验，减少误报 |
| 企业词表（`term`） | 项目代号、客户名、产品内部名、内部域名与 IP 段等 | 管理员维护的词表（D3），可选区分大小写与整词匹配 |
| 自定义规则（`custom`） | 管理员补充的前缀规则或正则规则 | 见 5.8 的校验约束 |

误报控制（借鉴 magpie 的经验）：

- UUID、长十六进制串、内容摘要、缓存键等标识符**整体不参与匹配**，避免把其中的片段误判为手机号或卡号；
- 匹配有边界要求：值两侧不能紧贴字母或数字；
- 白名单：管理员可放行特定值（整值匹配，不区分大小写）。

### 5.4 遮盖与还原

- **占位符格式：** `{{<类别>_<8 位短码>}}`，例如 `{{PHONE_k3v9x2mq}}`。短码由租户密钥对原值做 HMAC 得到：同一值在任何请求中都得到同一占位符，对话历史逐轮一致，厂商侧提示词缓存不失效；不同值不会共用一个占位符。
- **已识别值全文遮盖：** 一个值只要在请求的任一位置被识别（包括依赖上下文识别的，如“密码为 xxx”中的 xxx），该值在**同一请求的所有出现位置**都遮盖，不论其周围文字是否还能触发规则。识别分两步：先在全部文本（系统提示、各轮消息、工具调用参数与结果）上收集命中值，再统一替换。
- **Attempt 内已识别值集合：** 同一 Attempt 的后续请求中，上下文可能被 DSH 压缩，最初触发识别的文字（如“密码为”）不再出现，而值本身仍在。网关为每个 Attempt 在内存中保留已识别值集合（与令牌同生命周期，Attempt 终态即清除，不落盘、不进审计），后续请求先按该集合匹配，再跑规则。网关重启后集合丢失，由下一次请求重新识别；这一窗口内的漏报风险见第 8 节。
- **不持久化映射：** 网关在处理请求时得到“占位符 → 原值”映射，只在该请求及其回复期间保存在内存中。DSH 每轮都会重发完整上下文，映射可在下一次请求时重建；PF-04 恢复与重试不需要额外存储。
- **占位符必须跨请求稳定：** 除提示词缓存外，部分协议会校验历史思考内容的签名（Anthropic Messages 的 thinking 块签名针对模型当时看到的文本生成）。同一值在后续请求中若换成不同占位符，或某轮遮盖、下一轮未遮盖，回传的思考块就与签名不符，厂商会拒绝请求。因此：占位符只由原值与租户密钥决定，与请求、轮次无关；策略版本在 Attempt 内固定；已识别值集合保证同一值在 Attempt 内的处理方式不变。网关回传给 DSH 的思考内容按原样还原，DSH 下一轮带回时由网关再遮盖为同一占位符。
- **还原：** 厂商回复中的占位符还原为原值后再交给 DSH，包括流式文本、思考内容与工具调用参数。流式还原保留尾部一段（不超过最长占位符长度）再放行，避免占位符被拆在两个片段之间。
- **未知占位符：** 回复中出现本请求映射之外的占位符形式时原样保留，不猜测。
- **原文本身含占位符形式的文本**时先转义，保证还原不会误替换。

### 5.5 Provider 信任级别与策略

`model_providers` 增加 `trust_level`：`internal`（内部部署）/ `external`（外部厂商），新建 Provider 必须选择，默认不填不允许保存。存量 Provider 迁移为 `external`，由管理员确认后改为 `internal`。

默认策略（D5、D6）：

| 类别 | `internal` | `external` |
| --- | --- | --- |
| 密钥 | 放行 | **拦截** |
| 个人信息 | 放行 | 遮盖 |
| 企业词表 | 放行 | 遮盖 |
| 自定义规则 | 放行 | 按规则配置（遮盖或拦截，默认遮盖） |
| 图片与扫描件 | 放行 | 放行并记录 |

- 策略以版本发布，已发布版本不可修改；词表与规则的变更发布为新版本。
- Dispatcher 解析路由时把 `trust_level` 与当前策略版本一起写入路由快照（模型路由方案 4.2 的 `model_route` 增加 `trust_level`、`data_policy_version` 两个字段），同一 Attempt 的重试与恢复沿用同一版本。

### 5.6 拦截与失败语义

| 情形 | 结果 |
| --- | --- |
| 外部厂商请求中命中密钥 | 网关不转发，返回策略拒绝；Adapter 将 Attempt 以 `DATA_POLICY_BLOCKED` 结束，**不自动重试** |
| 令牌无效、过期或与路由不符 | 网关拒绝；Attempt 以 `MODEL_ROUTE_UNAVAILABLE` 结束 |
| 识别引擎异常 | **拒绝转发**（失败即关闭），Attempt 以 `DATA_POLICY_UNAVAILABLE` 结束；不得降级为不脱敏直发 |
| 网关不可用 | Attempt 失败，沿用 Runtime 不可用的错误分类；不得回退为 DSH 直连厂商 |

### 5.7 员工端提示（D7）

- 遮盖对员工无感，对话中不显示提示。
- 拦截时，回答区显示固定说明：“本轮请求包含 **<类别>**，按公司数据防护策略未发送给外部模型。”类别取 5.3 的名称（如“密钥”），不显示具体值或位置。
- 员工可在移除相关内容后重新发起；平台不自动重试。

### 5.8 词表与规则管理（管理端）

- 新增“数据防护”管理页：词表、自定义规则、白名单、Provider 信任级别概览、命中统计；先出可点击原型，确认后再开发。
- 词表与规则本身是机密，查看与编辑需要单独的权限，不默认授予所有管理员。
- 词表支持 CSV 导入；提供“检测试用”：输入一段文本，显示会被如何处理（只在管理端本地展示，不写入审计）。
- 规则校验：条数与长度设上限；正则须能编译、不能匹配空串；使用 RE2 语义或受限写法，防止回溯型正则拖垮网关。
- 发布：保存为草稿，发布后生成新策略版本，只对之后新建的 Attempt 生效。

### 5.9 审计（D8）

每个经过网关的请求记录：租户、用户、Run、Attempt、Provider 与模型、`trust_level`、策略版本、各类别命中次数、处理方式（遮盖 / 拦截 / 放行）、是否含图片。**不保存原值、原值哈希或原值周围的文本。** 保留期沿用平台现有审计日志。管理端运行详情可查看该 Attempt 的数据防护摘要。

## 8. 风险

| 风险 | 处理 |
| --- | --- |
| 遮盖降低回答质量（如分析客户名单时只能看到占位符） | 内部部署模型不处理；管理员可调整词表与白名单 |
| 误报导致正常内容被遮盖或拦截 | 校验位、边界与标识符排除；白名单；检测试用 |
| 漏报：词表外的机密、图片中的文字 | 第一期接受并在管理端说明；后续评估本地 NER 与内网 OCR |
| 网关成为单点与性能瓶颈 | 识别为线性多模式匹配；网关不可用时 Attempt 明确失败，不回退直连 |
| 依赖上下文识别的值，在上下文被压缩或网关重启后漏报 | 请求内全文遮盖；Attempt 内保留已识别值集合；网关重启窗口内的漏报接受并在 P2 观察 |
| 占位符不稳定导致思考块签名校验失败、请求被厂商拒绝 | 占位符只由原值与租户密钥决定；策略版本与已识别值集合在 Attempt 内固定；DLP-S0 与 P2 覆盖 Anthropic 协议路由 |
| 流式还原的切分与延迟 | 只保留不超过最长占位符长度的尾部 |
| 厂商把占位符改写（大小写、拆开） | 只还原精确形式；在 P2 中观察真实厂商的改写率 |
| DSH 升级后适配器地址或协议变化 | 纳入 DSH 升级准入检查：网关地址、令牌变量、流式格式 |

## 9. 验证

| 层级 | 内容 |
| --- | --- |
