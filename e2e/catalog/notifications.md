设计见 [站内通知方案](../../docs/design/notification-center-plan.md)，原型见方案页首链接。标注“待建”的 spec 文件随对应实施切片创建。

## 通知记录与接口（NC-S1）

### NC-01 与本人相关的四类事件各产生一条通知，读取时按当前权限解析

**优先级：** P1 · **角色：** 项目负责人、两位成员、一位非成员 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、真实 HTTP 接口（不调用模型）<br>
**前置数据：** 一个团队项目空间，负责人与成员甲在内；成员乙、非成员各一<br>
**spec：** `server/src/http/user-notifications-api.integration.test.ts`

1. 负责人把成员乙加入项目：成员乙收到一条“被加入项目”通知；负责人本人不收到。
2. 负责人在共享讨论中 @ 成员甲和非成员：只有成员甲收到“@ 我”通知；幂等重放同一条消息不产生第二条。
3. 负责人创建一个员工任务指派给成员甲：成员甲收到“任务指派给我”；把任务改派给成员乙：成员乙收到一条，成员甲不再新增；自己指派给自己不产生通知。
4. 成员乙把任务标记完成：任务创建人（负责人）收到“我创建的任务完成”；创建人自己完成时不产生通知。
5. 每条通知带触发人、所属项目、对象名称与跳转所需的 ID；名称在读取时解析，改名后读到新名称。
6. 成员乙被移出项目后，此前的通知仍在列表中，但不再返回项目和任务名称，标为“不可见”；任务被删除后，该任务的通知同样不可见。

**验收：** 通知与业务变更同一事务写入、可幂等重放；只有本人能读到自己的通知；失权后旧通知不泄露名称。

### NC-02 未读、已读与静音

**优先级：** P1 · **角色：** 项目成员 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、真实 HTTP 接口<br>
**前置数据：** 成员已有若干条未读通知，含 @ 我与任务类通知<br>
**spec：** `server/src/http/user-notifications-api.integration.test.ts`

1. 未读数等于未读且可见的通知条数；按“未读”筛选只返回未读通知，按时间倒序，可用游标翻页。
2. 标记单条已读后未读数减一；对他人的通知或不存在的通知标记已读返回“不存在”。
3. “全部标为已读”后未读数为 0。
4. 成员把该项目静音：该项目的任务类通知照常列在“全部”中，但不计入未读、不出现在“未读”页签；@ 我仍计入未读。
5. 在群组中打开对话（标记该群已读）后，该群的 @ 我通知同时变为已读；反之在通知中心读 @ 通知（单条或全部）后，群组“[有人@我]”标记同时消失。

**验收：** 未读口径与静音规则和方案 NC4、NC5 一致；已读只改本人记录，不改变业务数据。
