# 管理端模块权限

设计见[管理端模块权限方案](../../docs/design/admin-module-permission-plan.md)（AMP-S1 服务端、AMP-S2 员工与权限 / 钉钉模块与管理端前端）。证据层级与写法见[验收目录索引](../TEST-CATALOG.md)。

### AMP-P0-01 模块管理员只看到有权限的菜单并直接进入自己的模块

**优先级：** P0 · **角色：** 知识库管理员（冒烟测试身份，只有“修改企业知识库”） · **运行层级：** P0 冒烟服务、内存数据<br>
**前置数据：** 冒烟服务的模块管理员测试身份<br>
**spec：** `e2e/admin-module-permissions.spec.ts`

1. 打开管理端根地址，直接进入“企业知识库”，页面不出现加载失败或无权提示。
2. 侧栏只有“管理助手”“企业知识库”“接入规范”“接口文档”；Agent 管理、模型治理、员工与权限、钉钉集成、运营概览等菜单不显示，整组无权时分组标题也不显示。
3. 企业知识库的新建、授权调整与删除可以操作。

**验收：** 侧栏菜单与模块权限一致；首屏没有因无权模块的数据请求而报错。

### AMP-P0-02 打开无权页面的链接显示无权访问

**优先级：** P0 · **角色：** 知识库管理员（冒烟测试身份） · **运行层级：** P0 冒烟服务、内存数据<br>
**前置数据：** 同 AMP-P0-01<br>
**spec：** `e2e/admin-module-permissions.spec.ts`

1. 直接打开“模型治理”的地址。
2. 页面说明该页属于“模型”模块、当前账号没有查看权限，并给出返回自己落地页的入口；不显示模型治理的内容。

**验收：** 无权访问页有可访问的标题与返回按钮。

### AMP-P0-03 只读管理员看到修改操作不可用并知道原因

**优先级：** P0 · **角色：** 全模块查看的管理员（冒烟测试身份，`admin:read` + `audit:read`） · **运行层级：** P0 冒烟服务、内存数据<br>
**前置数据：** 冒烟服务的只读管理员测试身份<br>
**spec：** `e2e/admin-module-permissions.spec.ts`

1. 进入“企业知识库”，页面顶部说明当前只有查看权限、修改类操作不可用。
2. “新建知识库”等修改操作不可用。

**验收：** 只读说明与页面所属模块一致。

### AMP-P0-04 平台管理员按模块新建角色

**优先级：** P0 · **角色：** 平台管理员（冒烟测试身份） · **运行层级：** P0 冒烟服务、内存数据<br>
**前置数据：** 冒烟服务的员工与权限数据<br>
**spec：** `e2e/admin-module-permissions.spec.ts`

1. 进入“员工与权限 › 角色与权限”，点“新建角色”。
2. 弹窗不要求填写角色编码，说明编码由系统生成；功能权限按模块分区，每个模块有“查看 / 修改”，企业知识库另有员工端级别，数据防护另有保密词表。
3. 填写名称，勾选“企业知识库：修改”后保存。
4. 角色列表出现新角色，功能权限显示为“企业知识库·修改”等模块标签，编码为系统生成的 `role_` 开头的值。

**验收：** 弹窗表单控件都有可访问名称；保存后列表即时更新。

### AMP-01 员工与权限、钉钉模块的防提权规则

**优先级：** P1 · **角色：** 平台管理员、员工与权限模块管理员、钉钉模块管理员 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份<br>
**前置数据：** 平台管理员、只持有“修改员工与权限”的管理员、权限更高的员工、普通员工<br>
**spec：** `server/src/infrastructure/postgres/admin-module-permissions.integration.test.ts`

1. 员工与权限管理员新建或修改角色时，授出超出本人的权限或 `admin:*` 被拒绝；修改含本人没有权限的角色被拒绝；修改“平台管理员”角色被拒绝。
2. 给员工分配超出本人权限的角色、设置超出本人的数据范围被拒绝。
3. 操作自己的账号（分配角色、数据范围、停用、重置密码、撤销会话）被拒绝；操作平台管理员或权限比自己高的员工被拒绝；操作普通员工成功。
4. 新建角色不需要编码，系统生成 `role_` 开头的编码。
5. 钉钉模块管理员可以查看钉钉概览、给普通员工解绑；保存或清除钉钉应用配置被拒绝；给权限比自己高的员工代绑或解绑被拒绝。

**验收：** 每条拒绝都是 403 类型化授权拒绝，被拒绝的操作不留下数据变更。
